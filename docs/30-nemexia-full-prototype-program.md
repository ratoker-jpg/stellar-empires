**Документ:** `docs/30-nemexia-full-prototype-program.md`
**Статус:** программа (planning-only). Не заменяет и не отменяет активный batch-контракт `FULL-VISUAL-NAVIGATION-REDESIGN` (аудит PR #188, merge `ec2b1fe1`); каждая фаза программы стартует собственным docs-only Audit PR по протоколу `docs/28`.
**Baseline аудита:** `main` at `ec2b1fe1cd27a9512f0bc3a9a5bab7554a9aa0aa` (PR #188 merge), Release 1.0.0, schema v19 / save v6.
**Референс:** исследование Nemexia в `docs/research/` (96/96 help-материалов, 53 сохранённые страницы, `nemexia-final-complete-game-concept-2026-07-26.md`, `nemexia-navigation-and-ui-reference-2026-07-26.md`) + фактологический аудит `Nemexia_auto` (2026-08-08).
**Заказчик-контекст:** владелец репозитория. Цель — довести игру до полноценного оффлайн-прототипа Nemexia: **1 игрок + 100 ботов, рандомных по направленности мышления, союзы, переиспользование интерфейса/навигации Немексии**. Без мультиплеера и реальных игроков.

## 0. Методика и ярлыки фактов

Аудит выполнен сплошным чтением исходников (471 TS-файл, ~43k строк `src/`, 189 тестовых файлов, 350 документов) на baseline `ec2b1fe1`. Ярлыки:

- **[VERIFIED]** — подтверждено чтением кода/документов текущего `main` (файл:строка указывается, где критично).
- **[REF]** — подтверждено исследованием Nemexia в `docs/research/` (не баланс, а механика-референс).

## 1. Целевое состояние и Definition of Done

### 1.1 Формулировка цели

Одиночная браузерная кампания в духе Nemexia: игрок развивает империю от одной планеты до альянсовой или сольной победы, а мир вокруг него живёт по полноценным правилам: **100 автономных бот-империй** с уникальными детерминированными личностями, образующими **альянсы и коалиции**, ведущими экономику, разведку, войны и эндгейм через те же механики, что и игрок. Интерфейс и навигация воспроизводят **компоновку и поведение** Немексии (persistent header с ресурсами/энергией/адмиралом, меню, карта Universe → Galaxy → Solar system, зоны планеты), но с оригинальными ассетами и брендингом.

### 1.2 Definition of Done (проверяемые критерии)

Каждый пункт превращается в acceptance gate соответствующего Audit PR.

1. [ ] Новая кампания создаётся с выбором «1 игрок + N ботов» (N до 100) и пресетом вселенной; партия проходит **fresh game → terminal** без state injection — перманентный CI-гейт на 100 ботах.
2. [ ] Все 100 ботов получают личности из **детерминированного генератора** (seed + index): повторный запуск с тем же сидом даёт идентичные профили [DECISION].
3. [ ] Личности видимo различаются: ≥10 архетипов (агрессор, торговец, учёный, рейдер, строитель, изоляционист, оппортунист и т.д.), различимая статистика поведения в рейтинге/отчётах.
4. [ ] Поведенческие метрики подтверждают разнообразие: прогоны матрицы сидов дают распределение (агрессия, экспансия, наука, торговля) с ненулевой дисперсией — audit-гейт.
5. [ ] Боты формируют альянсы в течение кампании (не только в endgame), заключают/расторгают пакты, создают коалиции против доминирующего лидера.
6. [ ] Игрок имеет топ-уровневый экран «Союз» (создание/вступление/выход, состав, статус отношений).
7. [ ] Header в компоновке Немексии: серверное/игровое время, ресурсные чипы (металл/кристалл/газ), энергия, население, обломки, **адмирал-виджет (уровень/опыт)**, переключатель планет с координатами, глобальные предупреждения.
8. [ ] Главное меню — 7 пунктов как в референсе (Планета, Полёты, Галактика, Союз, Империя, Рейтинг, Командирский корабль) + hot-links (Лаборатория, Верфь, Космодром, Переработка, Торговля, Технологии).
9. [ ] Карта: Universe → Galaxy → Solar system с координатным переходом, поиском/фильтрами (по владельцу, альянсу), легендой цветов владения; 100 империй различимы.
10. [ ] Рейтинг игроков **и альянсов**, профиль империи (очки/статистика).
11. [ ] Отступники (Renegades) как NPC-цели с шпионажем и атакой; Sun Attack / Sun Support реализованы по канону `docs/25` (заглушки на карте сняты).
12. [ ] Очереди строительства поддерживают ≥3 слота в зоне (сейчас 1 [VERIFIED: `planet/buildingQueue.ts`]); очереди производства — без регрессии.
13. [ ] Schema v20 (масштаб империй/профили) и v21 (альянсы/дипломатия) с миграциями v19 → v20 → v21 по шаблону `migrateGameStateV*`.
14. [ ] Детерминизм: replay 100-бот кампании бит-в-бит воспроизводит состояние (checksum-матрица в CI).
15. [ ] Производительность: тик реального времени с 100 ботами укладывается в бюджет кадра; offline catch-up 7 суток ×10 при 100 ботах ≤ 2 минут; гейты в CI.
16. [ ] Размер сейва 100-бот кампании — в установленном бюджете (цель ≤ 8 МБ [INFERRED]); guard-тест.
17. [ ] Все стандартные гейты зелёные: `npm run check`, Browser E2E, production Pages smoke, axe WCAG 2.1 A/AA.

### 1.3 Явные не-цели (non-goals)

- Мультиплеер, сетевой код, аккаунты, античит — не делаем никогда в этой программе.
- Копирование HTML/CSS/JS/артов/названий/брендинга Nemexia — запрещено правами и правилами `docs/29` (non-port граница). Только компоновка/паттерны поведения.
- Кредитная/банковская подсистема — исключена решением `doNotCreateCreditSubsystemForGhostField`; банк остаётся UNKNOWN-UNTOUCHED [VERIFIED: `project-status.json`].
- Аукцион, Premium/Platinum, монетизация, ситтеры, vacation — исключены (gap analysis `docs/18`).
- Точное воспроизведение формул Nemexia (кривые стоимости, BP-формулы) — источники неполны [REF: пробелы исследования]; баланс делаем собственным harness'ом.

## 3. Гэп-анализ: текущее состояние → целевой прототип

### G-1. Масштаб империй: 4 → 101 (критический разрыв)

Код предполагает ровно 4 империи во многих местах: `createInitialGameState.ts:64` (массив empires), `universe/model.ts:85` + `galaxy/generateGalaxy.ts:30` (HOME_OWNERS — 4 дома), нормализация `botAutomation` только по известным профилям, UI-ремапы `pveOperationsPlannerLegacy.ts:65–170` (viewer-state с `__hidden-player-for-bot-pve-view__`), ветвления на `empireId === 'player'` в reducer/отчётах/рейтинге. Вселенная campaign (6×27×24 = 3888 позиций, ~48% занятости → ~1850 планет) вмещает 100 империй по 3–8 колоний — геометрия не блокирует, но материализуется только galaxy 1 [VERIFIED]. Нужно: параметризованное создание N империй, назначение 100 домов детерминированным разрежением, материализация всех 6 галактик, ревизия всех `empireId`-ветвлений.

### G-2. Личности ботов: 3 статичных профиля → 100 уникальных

Сейчас: `profiles.ts:14–42` — три профиля (industrial/explorer/aggressive), различие — порядок приоритетов развития и `maxAttackRiskPermille` 700/800/900; интервалы решений 600/300/450с; **рандомизации нет**, `getBotProfile` ищет по empireId [VERIFIED]. Планировщики потребляют профиль точечно; `memory.ts` — только UI-сводка, планировщики память не используют; единственная адаптация к исходам — recoveryBias по 3 последним PvP-боям [VERIFIED]. Нужно: генератор личностей (D-2), потребление черт планировщиками, долговременная память отношений.

### G-3. Союзы и дипломатия: endgame-заготовка → полноценная система

Сейчас: альянсы живут только в `endgame/participation.ts` (имя 3–40 символов, join/leave, история 64, соло-участие) и нужны для Solar War; политика 3 ботов захардкожена (aegis→"Aegis Vanguard", synod→"Synod Compact", veyra solo) [VERIFIED]. Нет: двусторонних отношений (война/нейтралитет/пакт), альянс-очков, коалиций, реакции на агрессию, UI-экрана союза верхнего уровня. В референсе [REF: doc 13 social]: NAP (отмена 72ч), War (старт 12ч, отмена 168ч), альянс-очки (перевозки/BP/гарнизон), уровни 1–25 с бонусами. Для оффлайна адаптируем: упрощённые отношения + боты-дипломаты.

### G-4. Производительность планировщика на 100 ботов

Сейчас: один бот-десижон за одну операцию симуляции (`campaign/time.ts:316–325`), бюджет 256 операций/чекпоинт; worker не подключён; дедуп `JSON.stringify`; `pveOperationsView` пересчитывает полёты для всех объектов на каждый вызов [VERIFIED]. При 100 ботах с интервалами 300–600с на игровой день ×1 (~86400с) каждый бот делает ~150–290 решений/день → **15k–29k решений на игровой день** против ~600–900 сейчас (×20–30 рост). Без батчинга/воркера/индексов тик и catch-up не уложатся в бюджеты (DoD-15).

## 4. Ключевые архитектурные решения

Каждое решение [DECISION] фиксируется здесь и подтверждается/уточняется Audit PR соответствующей фазы. Для каждого приведены отклонённые альтернативы с обоснованием.

### D-1. Модель 101 империи — расширение текущей, а не эмуляция

**Решение:** `empires` становится списком из `1 + N` идентификаторов: `'player'` + `'bot-<NN>'` (NN 01..100), N задаётся в `campaignSettings` (новое поле `botEmpireCount`, дефолт 100 для нового пресета «Nemexia prototype», совместимые дефолты для старых сейвов — 3). Дома назначаются детерминированным разрежением по позициям галактик (seed-хешированный обход систем, по одному дому на систему до исчерпания). Материализуются все галактики пресета.

**Альтернатива A (отклонена):** 100 ботов эмулировать поверх 4 империй (несколько «личностей» на империю). Отклонено: ломает рейтинги, альянсы, разведку, переговоры, галактическую карту — всё построено вокруг empireId; экономия мнимая, а честность мира («каждый бот — империя через те же команды») — ядро ценности.

**Альтернатива B (отклонена):** переход на ECS/полный переписывание симуляции. Отклонено: риск детерминизма и потеря 650 тестов; текущее ядро выдержит масштаб после D-4.

### D-2. Генератор личностей — детерминированный, архетипный, с вектором черт

**Решение:** `generateBotProfiles(seed, count)` → 100 × `GeneratedBotProfile`:
- **архетип** (≥12: aggressor, raider, industrialist, scientist, trader, expansionist, turtle, opportunist, opportunist-predator, diplomat, berserker, architect) — выбирается взвешенно по hash(seed:empire:archetype);
- **вектор черт** 0..1000: aggression, riskTolerance, expansionDrive, researchFocus, economyFocus, fleetFocus, defenseFocus, diplomacyBias, opportunism, deception (маскировка намерений в видимой статистике);
- **policy-производные**: порядок приоритетов развития (взвешивание существующих конвейеров), `maxAttackRiskPermille` (300–1200), интервалы решений (240–900с, задают «реактивность» личности), предпочтения PvE-портфеля, пороги арены/экспедиций, склонность к альянсам и к коалициям против лидера.

Генератор чистый, детерминированный, живёт в `simulation/bots/profileGenerator.ts`, профили сериализуются в state (v20) для честного save/load. Существующие 3 профиля становятся частным случаем (пресеты архетипов).

**Альтернативы (отклонены):** обучение с подкреплением/ML — недетерминизм и неподдающийся аудиту контур; 100 рукописных профилей — не масштабируется и не даёт «рандомности по направленности мышления».

### D-3. Планировщик ботов — батчинг в тике, worker как вторая ступень

**Решение (ступень 1):** `runBotScheduler` принимает список из K due-профилей за операцию (K=16 начально, тюнинг по аудиту); дедуп-ключи — стабильные строки `kind:ids` вместо `JSON.stringify`. Ступень 2: включение существующего `BotAutomationController`-воркера с **BotPlanningSnapshot** (минимальный слепок, а не полный GameState) — только после perf-аудита фазы 1, если тик всё ещё вне бюджета.

**Альтернатива (отклонена):** перенос всех ботов в воркер сразу. Отклонено: воркер получает полный GameState по посту (сейчас так и есть [VERIFIED]) — при 100 империях это мегабайты на каждое решение; сначала срезать объём и батчингом доказать бюджет, потом решать о воркере.

### D-4. Производительность симуляции — индексы и кэши с точной инвалидацией

**Решение:** (1) Map-индексы планет/флотов по empireId и координате, строятся лениво в reducer-сессии, не попадают в state (не ломают checksum); (2) кэш `galaxyIntelligenceView` по (stateReference, empireId) с инвалидацией по счётчику изменений intelligence/planets; (3) `pveOperationsView` — кэш на операцию планировщика. Всё — чистые оптимизации без изменения результатов (гейт: бит-в-бит равенство checksum до/после на organic-сценарии).

**Альтернатива (отклонена):** денормализация state ради скорости — ломает replay и валидацию сейва.

### D-5. Альянсы и дипломатия — first-class state v21

**Решение:** `AllianceState` (id, имя, лидер, члены, создан) + `DiplomacyState` (двусторонние отношения empire↔empire: war / nap / neutral + grudgeScore + история событий с лимитом). `endgame/participation.ts` переключается на AllianceState (миграция v21 переносит endgame-альянсы). Команды: CREATE_ALLIANCE, JOIN_ALLIANCE, LEAVE_ALLIANCE, DECLARE_WAR, PROPOSE_NAP, ACCEPT_NAP, BREAK_NAP, MAKE_PEACE (все через reducer с валидацией — боты и игрок равноправны). Боты-дипломаты: utility-оценка (сила, история обид, расстояние, угроза лидера по рейтингу), коалиция против доминирующего (порог: лидер > 2× медианы силы [DECISION, тюнинг аудитом]). Альянс-очки: агрегат перевозок/BP (без уровней-бонусов в первой версии — они из референса [REF doc 13], отнесены к post-prototype).

**Альтернатива (отклонена):** оставить альянсы в endgame и добавить «пакты» отдельно — два источника правды о союзах, конфликт миграции и UI.

### D-6. UI — перекомпоновка существующего DOM-shell по паттерну Немексии, без копии

**Решение:** сохраняем стек (DOM shell + hash-router + Phaser-карта; без React [VERIFIED: docs/20 «не делать React»]); Phase 0 (активный batch) уже унифицирует shell/HUD. Далее: header по референсу (G-5 таблица), меню 7 пунктов, hot-links, зоны/карточки, лента событий. Стилистика — собственная (design tokens), компоновка/поведение — по референсу. Ассеты — только собственные/процедурные (политика `docs/26`).

**Альтернатива (отклонена):** копировать вёрстку Nemexia — нарушение non-port границы и прав; «паттерн, не копия» [REF: doc 14].

### D-7. Персистентность — v20/v21, бюджеты, масштабируемые лимиты

**Решение:** v20 = botEmpireCount + сгенерированные профили + дома; v21 = альянсы/дипломатия. Лимиты истории на империю масштабируются: intelligence 64/128 остаётся на империю, но событийные логи империй-ботов сжимаются (ботам достаточно 64 команд/событий [DECISION]); state checksum не меняет алгоритм. Save-size guard-тест с бюджетом. Catch-up: чекпоинт каждые 256 операций сохраняется, но операция теперь = K ботов (D-3) — число чекпоинтов не растёт пропорционально ботам.

**Альтернатива (отклонена):** отдельные сторы для ботов (splitted save) — усложнение atomicity; текущий единый конверт с checksum доказал себя (recovery-гейты #187).

### D-8. Детерминизм и честность ботов — неизменный контракт

**Решение:** все новые системы (генератор профилей, дипломатия) — чистые функции от (seed, state); боты действуют только через `executeCommand` с reason code; расширение reason-кодов дипломатии/личностей фиксируется в аудите; replay-гейт на 100 ботов; новые органические сценарии fresh→terminal на 100 ботах — перманентные CI-гейты (по образцу #174).
